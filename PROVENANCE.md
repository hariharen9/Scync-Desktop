# PROVENANCE

The backend code in `src/backend/` is **vendored** (copied, not linked) from the
Scync CLI and Scync web app sources, as required by the desktop spec. This file
records the exact source of every vendored file and every deliberate deviation.
Reference snapshot: `scync-cli` v0.1.4 source tree and `scync` web repo
(`AGENTS.md` verified 2026-09-02), both provided in `scync-source.zip` /
`scync-source/`.

## Ported with an explicitly minimal diff

| Desktop file | Source | Diff |
|---|---|---|
| `src/backend/firebase.ts` | `scync-cli/src/core/firebase.ts` | Same `HOSTED_CONFIG` values. Removed every Node dependency (`node:fs`, `node:os`, `dotenv`, Node `FilePersistence`); auth now uses the Firebase JS SDK's default IndexedDB browser persistence. Config override no longer reads `process.env` at runtime — it comes from the Tauri app-config file via `setBaseConfig()` (self-hosters edit `scync-desktop.json` in the OS config dir). Emulator support preserved. |
| `src/backend/vault-session.ts` | `scync-cli/src/core/vault-session.ts` | Removed the `AgentClient` background-agent branch entirely (the desktop app is its own long-lived process; the in-process key is the session). Kept `deriveKey` + `checkVerifier` unlock logic and the `VaultSession` interface (minus `isAgent`). CLI-only concerns (`promptMasterPassword`, config parsing) belong to the UI layer here. |
| `src/backend/shares.ts` | `scync/packages/core/src/firestore.ts` (sharing section) | One deliberate deviation: `createShare` **always** returns `https://scync.space/share/<id>#<key>`. The web app uses `window.location.origin` when available; in a desktop webview that is the Tauri local origin (`tauri://localhost` / `http://localhost:1420`), which a recipient cannot open. Hardcoding the web origin is the only correct fix; flagged here per spec. Everything else — `Timestamp.fromDate` expiry, `serverTimestamp()` createdAt, base64url key fragment, transactional `consumeShare` (read → validate → decrypt → atomic increment) — is unchanged. |
| `src/backend/domains.ts` | `scync/packages/core/src/firestore.ts` (password/project/ssh/totp/cert write + update sections) | Extracted the CRUD functions the CLI core lacks (the CLI only reads/creates those domains). Write shapes, field names, and `serverTimestamp()` usage unchanged. Added `updateSSHKey` / `updateCertificateMetadata` (metadata-only edits of already-plaintext fields). |
| `src/backend/subscriptions.ts` | `scync/packages/core/src/firestore.ts` (subscribe* functions) | Whole-collection `onSnapshot`, no orderBy/where, client-side filtering — same as `subscribeToSecrets` in the CLI core. |
| `src/backend/utils.ts` | `scync/packages/core/src/utils.ts` | Byte-identical `getAttentionSecrets`. |
| `src/backend/ssh.ts` | `scync/packages/core/src/ssh.ts` | Byte-identical ( RSA-4096 via node-forge + WebCrypto ed25519). |
| `src/backend/certificates.ts` | `scync/packages/core/src/certificates.ts` | Import path extension change only (`./types` → `./types.js`). |
| `src/backend/share-keys.ts` | `scync/packages/core/src/crypto.ts` (share-key section) | Byte-identical functions (`generateShareKey`, `exportShareKey`, `importShareKey`); kept out of `crypto.ts` so the vault-only crypto entry point stays byte-identical to the CLI. |
| `src/generated/google-client.ts` (generated) | generated by `scripts/generate-google-client.mjs` | Script ported from `scync-cli/scripts/generate-google-client.mjs` (same env vars, same preserve-existing behaviour, git-ignored). |

## Local new files (no external source)

- `src/backend/errors.ts` — `ConflictError` copied from `scync-cli/src/cli/errors.ts` (the CLI core imported it from the CLI layer, which must not ship in the desktop). Message text preserved; `--force` wording replaced because the desktop UI has no force flag. `VaultNotInitializedError` message taken verbatim from the CLI's `unlockVault`.
- `src/backend/index.ts` — barrel re-exports.

## Guarantees

- No file under `src/backend/` imports Node built-ins or CLI modules.
- Crypto parameters, Firestore paths, write shapes, and share format are
  unchanged from the sources above. Any future edit to this directory must be
  recorded here with its reason.
- The app must never write `meta/vault` (setup, password change, biometrics,
  recovery): those functions of `firestore.ts` are dead code in this repo —
  available because the file is copied whole, but never called from the UI.
